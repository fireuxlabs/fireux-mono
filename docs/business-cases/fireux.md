# FireUX Business Case
Authority: Internal planning
Updated: 2026-05-26

## Product Thesis
FireUX is the platform operating system for building and running ecosystem apps from one shared Nuxt and Firebase core.

## Audience Map
- Builders who need to launch domain apps without rebuilding auth, runtime, routing, layout, deployment, and app metadata every time.
- Operators who need a consistent console pattern across multiple apps, tenants, modules, and user roles.
- Product owners who need white-label app surfaces, shared modules, and deployable ecosystems.

## Business Case
The value of FireUX is speed with alignment. It turns repeated app infrastructure into a shared runtime so each ecosystem can focus on its domain: kitchens, cleaning, local supply, property portfolios, SEO discovery, QR tools, or guest guides.

FireUX should make new apps cheaper to start, easier to govern, and harder to fragment. Its business value comes from reusable platform contracts, shared components, app registries, module composition, tenant-aware runtime, and deployment discipline.

## Engagement Angle
Use FireUX when the customer or builder needs more than a landing page: they need a real app surface, a console, users, records, modules, routes, roles, SEO pages, and a path to launch.

## Meta Dissemination
The public meta should explain FireUX as a platform for ecosystem apps, not as a generic Vue starter. It should point to apps, modules, projects, ecosystems, and development paths.

## Solution Direction
- Launch a domain app
- Build a Firebase Nuxt app
- Create a white-label app
- Add an operator console
- Compose runtime modules
- Ship a tenant app
- Standardize app metadata and SEO surfaces
