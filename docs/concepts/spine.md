## App and Ecosystem composition spine

The App's native Nuxt config selects the [standard App builder](../../packages/extensions/fireux-app/src/config.ts)
or [Main App builder](../../packages/extensions/fireux-ecosystem/src/config.ts)
when it uses a bundle. A named Ecosystem supplies shared Firebase bindings
and real cross-extension composition. Domain modules and native layers
supply capabilities. Core provides their neutral foundation. See
[App configuration](app-config.md), [App roles](family-tenant-global.md),
and the [package contract](runtime-package.md).

Installing a surface establishes availability. Membership, entitlements,
target scope and active domain policy determine access. Use the current
[Misebox App](../../projects/misebox/misebox-app/nuxt.config.ts)
and [La Tap tenant](../../projects/misebox/la-tap-berne/nuxt.config.ts) as
concrete composition references. Codex Map uses this section's source links
and exact concept ID for optional task associations.

## Family growth lifecycle

1. Prove one complete baseline at the seam being tested.
2. Add a real sibling for a named product difference. Reuse proven lower
   mechanics early. Deliberate bounded repetition can preserve independent
   evolution.
3. Verify a material difference in authority, inputs, lifecycle, workflow or
   presentation. Naming differences alone supply little evidence.
4. Compare current consumers after differentiation. Promote the shared
   responsibility only when real members still use it for the same reason
   and the contract can be verified. Keep justified differences local.

Record what is accepted, transitional, unexplained, or still to confirm in
the smallest relevant owner map. A temporary compatibility path needs an
owner and removal trigger. Avoid turning a comparison into a generic layer
or a folder requirement.
