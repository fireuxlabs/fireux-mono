Every legacy Nuxt config reaches a common missing Core export from `fireux-app/src/config.ts` or its defaults. Core no longer exports `config/app/*`, `config/module/*`, the old runtime, or the old Core module. The 27 legacy configurations therefore have a source-level resolution blocker against this reset Core. No per-App builds were attempted and older releases may have built against older Core. Each of the eight `packages/ecosystem/fireux-{bringli,buenohost,fireux,granite,misebox,sharer,slap,werkbox}/src/module.ts` imports retired Ecosystem wiring. Bringli, BuenoHost, FireUX, Granite and Misebox can inject extension modules conditionally from old workspace registration. Their named layers expose Supplier; Property and Reservations; Projects; Property, Compliance, Documents and Tasks; and Kitchens respectively. Inspect owner behavior before carrying forward any package. Ecosystem packages provide capabilities. The App config assembles them, and the Firestore Ecosystem document owns its facts.

Legacy configs declare display metadata and role alongside App identification and functional/organizational relationships. App documents should own name, short name, published contact/assets, role and membership. Retain actual native navigation, presentation, auth and deployment settings where used. Authored product literature can remain local; private AI context stays private and needs a concrete owner. Legacy `ecosystem` selects a module, `ecosystemId` identifies stored membership, and `projectId` is a FireUX Project entity input. They are distinct from Firebase project ID. Legacy `databaseId` selects a named database and belongs to environment with the Firebase project, Admin credentials and emulator hosts. Keep a separate private Ecosystem scope for bounded deployment operations. `cleanbox`/Werkbox is a concrete mismatch to resolve without renaming IDs. Legacy Firebase setup reads `APP_DOMAIN`, `NUXT_FIREBASE_APP_ID`, optional Web API/developer values and ecosystem Firebase defaults. Those are historical inputs. The new system uses deployment-specific native runtime keys.
