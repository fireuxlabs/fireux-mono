# Yellow Velo SEO and Commerce Baseline

This captures the current `yellow-velo.ch` SEO and commerce shape before FireUX
design or ecommerce migration work. Treat Charlie Whitworth's existing setup as
the baseline strategy. Change only with evidence, URL mapping, and redirect
coverage.

## Baseline Position

The current site is not just a brochure. It combines:

- WordPress
- WooCommerce
- Yoast SEO
- Google Site Kit
- WooCommerce product filters
- product brand taxonomy
- Stripe / GoDaddy WooCommerce payment wiring
- The Events Calendar
- social identity links for Facebook, Instagram, and TripAdvisor

Assume SEO choices are intentional until disproven. Some sitemap entries look
like inherited theme/demo pages, but they should be audited before removal.

- product id
- name
- slug
- permalink
- simple/variable type
- categories
- brands
- prices
- stock state
- images
- attributes and variations
- related/upsell/cross-sell links

Current sample findings:

- `61` simple products.
- `32` variable products.
- `525` product image references across the 93 products.
- Current API image alt fields appear empty in the public Store API.
- One product slug is numeric: `/product/7043/`.

The numeric product URL needs specific handling in the redirect map. Image alt
text is an SEO/accessibility improvement opportunity, but should be filled from
real product names/context rather than generated blindly.

## Migration Principle

Moving away from WooCommerce is acceptable if FireUX + Stripe becomes the real
commerce system. The SEO risk is not leaving WooCommerce. The SEO risk is losing
URL continuity, content, structured data, category/brand meaning, or internal
links.

FireUX migration must preserve or map:

- `/shop/`
- `/product/<slug>/`
- `/product-category/<category>/`
- `/brand/<brand>/`
- current service/tour/rental/repair URLs
- canonical titles and descriptions
- product descriptions and excerpts
- product images and image metadata
- category and brand groupings
- stock and purchasability state
- Product/Breadcrumb/Organization/WebSite JSON-LD intent
- sitemap coverage

## FireUX Target Shape

Use the existing FireUX product canon:

- canonical product records: `products/{productId}`
- product prices: `products/{productId}/prices/{priceId}`
- product pages: `/products` and `/products/{slug}` where the package owns that
  surface

For Yellow Velo, preserve old Woo URLs with one of these strategies:

1. Keep compatible public routes such as `/product/{slug}` and `/shop`.
2. Or 301 redirect old URLs to new FireUX URLs with a complete URL map.

Do not launch a FireUX shop at `/products` while abandoning `/product/<slug>/`
without redirects.

## Stripe Migration Notes

Stripe should become the payment provider for FireUX products, but it does not
replace product SEO. Stripe product/price ids should be stored as provider
metadata and on `ProductPrice` records.

Keep WooCommerce ids in FireUX product metadata during migration:

```text
metadata.woocommerce_id
metadata.woocommerce_slug
metadata.woocommerce_permalink
metadata.woocommerce_type
metadata.woocommerce_categories
metadata.woocommerce_brands
metadata.woocommerce_attributes
metadata.woocommerce_variations
```

## Required Before Cutover

- Export all products from WooCommerce API or admin CSV.
- Export or mirror all product images.
- Build a URL map for pages, product pages, category pages, and brand pages.
- Generate 301 redirect config.
- Preserve canonical, title, description, OpenGraph, and JSON-LD parity.
- Generate FireUX sitemap entries for migrated URLs.
- Confirm cart, checkout, tax, shipping, stock, email, and refund workflows.
- Confirm Search Console ownership and submit the new sitemap after launch.
- Keep WooCommerce live until FireUX product import and checkout have passed
  smoke tests.

Tommy's brief includes:

- custom / vintage bikes
- rentals
- tours
- workshop services

These should appear in page copy, service taxonomy, product/category language,
SEO descriptions, and internal links. They should not be forced into every asset

## Photography Carryover

- homepage/category hero images
- product galleries
- custom/vintage bike story pages
- tour/location pages
- optional footer page such as `/photography`, `/rides`, or `/journal`

Temporary stock imagery is acceptable only during design scaffolding. Replace it
before launch with owned landscape photography where possible.
