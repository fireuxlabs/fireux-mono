# FireUX Server System

## Overview

- All server code runs under Nitro (Nuxt 4) and exposes lightweight HTTP endpoints that sit in front of Firebase Admin, Google APIs, and Stripe.
- Each app project may host its own `/server` directory for bespoke endpoints. The shared `fireux-core` and `fireux-places` packages ship reusable runtime handlers that Nuxt apps auto-mount under `/api/*` when the module is installed.
- Firebase Admin bootstrap lives both in app space (`projects/fireux/fireux-app/server/utils/firebase-admin.ts`) and in shared modules via `fireux-core/src/runtime/server/utils/getAdmin.ts`. Both hydrate admin apps using either inline JSON (`FIREBASE_SERVICE_ACCOUNT`) or split env vars plus optional storage bucket normalization.

## Source Layout

### App-level server (`projects/fireux/fireux-app/server`)

| File                             | Route / Purpose                                                                                                                                                     |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `api/hello.get.ts`               | Health+Firestore sampler that hits the registry database, lists non-diagnostic collections (max 10), and returns timestamp plus error info. Useful for smoke tests. |
| `api/firebase-admin.ts`          | Local helper endpoint (mirrors `server/utils/firebase-admin.ts`) that exposes `getFirebaseAdminApp`/`getFirestoreDb` helpers for other handlers.                    |
| `api/docs-manifest.get.ts`       | Returns the Content manifest generated by `~/utils/docsManifest.server`, powering the `/docs` experience.                                                           |
| `api/docs/images.get.ts`         | Legacy endpoint kept temporarily; now responds `410 Gone` instructing clients to use the `/docs/images` page served by Nuxt Content.                                |
| `server/utils/firebase-admin.ts` | Shared helper for `hello` and future handlers. Loads service-account JSON from env or disk, caches the `firebase-admin` app, and exposes Firestore handles.         |

### Core runtime module (`packages/core/fireux-core/src/runtime/server`)

| File                                          | Route / Purpose                                                                                                                                                                                                     |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `utils/getAdmin.ts`                           | Singleton initializer (same contract as the app helper) plus storage bucket normalization.                                                                                                                          |
| `api/app.get.ts`                              | Returns the hydrated app manifest (name, theme colors, assets, API metadata) derived entirely from environment variables.                                                                                           |
| `api/app/theme.get.ts`                        | Similar to `app.get`, but optimized for cross-origin consumption: sets permissive CORS headers and returns only theming plus identity data.                                                                         |
| `api/app/env-check.ts`                        | Comprehensive environment + brand asset validator. Ensures required client/server env vars exist, inspects service-account availability, and validates brand images on disk (dimensions + presence).                |
| `api/app/ensure-app.post.ts`                  | "App initialization" orchestrator. Provisions default Stripe products (Pro, Enterprise) and writes minimal metadata to Firestore via `/api/firestore/update-document`.                                              |
| `api/proxy/image.get.ts`                      | Sanitized image proxy that fetches remote images with basic protocol validation, returning them with cache headers.                                                                                                 |
| `api/inject-trace.post.ts`                    | Server-side sink for client diagnostics. Accepts structured logs/errors and prints them to the server console for observability.                                                                                    |
| `api/firestore/update-document.post.ts`       | Generic Firestore writer. Initializes Firebase Admin dynamically, accepts `{ collection, documentId, data, merge }`, and performs the write (supports ping/pong tracing).                                           |
| `api/health.get.ts`                           | Reports whether the server sees a service-account file/string and echoes selected runtime config, helping CI guards.                                                                                                |
| `api/storage/upload-avatar.post.ts`           | Accepts either `{ url }` JSON or raw binary, stores a user avatar under `users/{uid}/avatar.jpg`, and returns the signed download URL.                                                                              |
| `api/notifications.get.ts`                    | Stub endpoint that currently returns an empty array (placeholder for future notification feeds).                                                                                                                    |
| `api/stripe/create-product.post.ts`           | Creates a product plus optional prices in Stripe, then notifies `/api/stripe/update-firestore` (not yet in repo) if available. Guarded by `STRIPE_SECRET_KEY`/SDK presence.                                         |
| `api/stripe/create-subscription.post.ts`      | Creates subscriptions for existing customers/prices, mirrors state into Firestore (`apps/{appId}/users/{userId}/subscriptions/{subscriptionId}`), and updates the user document with current subscription snapshot. |
| `api/stripe/version.ts` & `stripe/version.ts` | Central Stripe API version constant (`2025-08-27.basil`) shared by the Stripe handlers.                                                                                                                             |

### Places extension module (`packages/extensions/fireux-places/src/runtime/server`)

| File                             | Route / Purpose                                                                                                                                                                                 |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `utils/places-api-key.ts`        | Helper that resolves the Google Places API key from runtimeConfig, public Firebase config, or environment.                                                                                      |
| `api/places/autocomplete.get.ts` | Thin proxy over Google Places Autocomplete with IP-based in-memory rate limiting. Returns up to four structured predictions near a default Bern, CH lat/long unless overridden by query params. |
| `api/places/details.get.ts`      | Fetches a detailed place record (business metadata, address, etc.) for a given `place_id` via the same API key resolver.                                                                        |
| `api/places/logo.get.ts`         | Best-effort logo resolver: crawls the business homepage, scores favicon/logo candidates, and falls back to Clearbit → Unavatar → Google S2 → Picsum placeholders.                               |

## Execution Model

- When a Nuxt app installs `fireux-core` or `fireux-places`, Nuxt auto-registers the exported server handlers, so any FireUX tenant automatically gains `/api/app/*`, `/api/firestore/*`, `/api/stripe/*`, and `/api/places/*` routes without copying files.
- The FireUX app project currently hosts bespoke routes (`/api/hello`, `/api/docs/*`) that are only compiled into that project’s deployment. Other tenant apps can add their own `/server` directory following the same Nitro conventions.
- Firebase Admin bootstrap is intentionally duplicated: module consumers call `getAdmin()` from `fireux-core`, while the FireUX app’s local helpers exist to unblock routes before the shared package is published. Consider consolidating them later.

## Operational Notes

- Environment contracts: service-account access via either `FIREBASE_SERVICE_ACCOUNT` (JSON), split keys + `FIREBASE_PRIVATE_KEY`, or `GOOGLE_APPLICATION_CREDENTIALS`. Stripe handlers require `STRIPE_SECRET_KEY` and the `stripe` npm dependency.
- Brand assets validated by `env-check` must live under `public/img/core/brand` (FireUX default) or `public/img/ecosystem/*` for tenant packages.
- To add a new server route, place a `.ts` file under `server/api` (app scope) or `src/runtime/server/api` inside a shared package. Nitro automatically maps `*.get.ts`, `*.post.ts`, etc., to HTTP verbs.
